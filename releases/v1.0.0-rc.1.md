# 1.0.0-rc.1 — Claude Code and Codex configuration with guarded application

Release candidate date: 2026-11-02 (Asia/Seoul). Channel: **next**. Stable 1.0.0 publication requires a separate maintainer decision after reviewing RC results.

## Product contract

This is a reviewable, project-aware Agent configuration tool. Either host can configure Claude Code, Codex or both. Without an explicit target, the executing host is the default; the Skill announces its project/target and leaves other targets untouched. `--agent all` remains a Skill-installation selector, not a request to generate both Agent trees.

Claude Agents use project Markdown/YAML; Codex Agents use standalone project TOML with target-specific models, reasoning and feature controls. Codex parent sandbox/provider/MCP settings are not overridden by custom Agent files. Base settings, AGENTS.md, global configuration and runtime Agent invocation remain outside ordinary configuration scope.

## Guarded file application

The Skill authors complete candidates through prepare, reviews them, checks their digest, and applies only that checked candidate through the new Python helper. Both-target requests preflight both trees before writes. Existing comments/extensions/languages, byte formats and explicit constraints remain preservation requirements. Deletion/rename/consolidation requires exact target/path allowances from the user's request.

Stale inputs, unsupported formats, unauthorized file removal, links/junctions and static errors are refused. Identical files preserve mtimes. Conditional recovery preserves concurrent/uncertain outputs and reports backups and unresolved paths. Forced termination may require manual recovery. The helper is not a sandbox, semantic reviewer or atomic multi-file transaction; direct writes by other programs are outside its control.

## Install or upgrade

```sh
npx --yes @woody_s/configure-subagents@next install --agent all
npx --yes @woody_s/configure-subagents@next update --agent all
```

Pin `@1.0.0-rc.1` for reproducibility. Install/update copies Skill files only, preserves both existing Agent trees, recognizes verified unmodified alpha.8 and older published payloads, and refuses customized Skills for manual merge. Node.js 22+ remains dependency-free. Python 3.10+ needs PyYAML for Claude and conditional tomli for Codex on 3.10; 3.11+ uses tomllib. No dependency installation or model call is part of npm installation.

## Validation and remaining work

Automated validation covers both formats, stale-candidate/original checks, exact deletion allowances, cross-target failure recovery, concurrent changes, byte/mtime preservation, parser failures and the exact 21-file offline tarball. Independent code review found a checked-digest race and evaluation-input/sanitizer issues; those were corrected with reproductions/regression tests before this candidate.

The **22-session authenticated installed-RC campaign is pending at initial publication**. See the [current RC report](https://github.com/ChiwooSong/configure-subagents/blob/main/evals/RC1_BEHAVIOR.md) for subsequent results. Earlier alpha successes do not count as current-RC behavior passes. Exact-commit CI and registry artifact receipts are attached/linked from the GitHub release.

The [release checklist](../docs/V1_RELEASE_CHECKLIST.md) now distinguishes release-blocking file-tool defects from disclosed model/host judgment limits. It does not require three flawless semantic pairs or rerunning until green. Previous first-pass/cross-review failures remain documented, not retroactively passed. Actual Agent execution, measured performance/savings and universal language/model/OS accuracy are not claimed.

## Post-publication results — November 3, 2026

The original 22 session outcomes are recorded: 21 native final receipts plus a reconciled last Claude real-both repeat observation. Seven fresh repeats have identical request/start bindings and unchanged observed file bytes/mtimes, including application records. The last repeat's final report and current equality with apply output were observed, but its window disappeared without a native exit receipt; its return code and separately persisted start/end binding remain unverified. No replacement session was launched. Claude validation-only commands were permission-blocked, not passed.

All eight real-project outcomes used frozen copies that accidentally omitted module sources. The capture harness was corrected and all six current static CI jobs passed with 116 Python tests; the 14-file installed Skill payload did not change. The maintainer declined extra model sessions, so module-inclusive project behavior remains unverified. Current outputs also retain some overbroad workflow/memory-scope wording, and historical first-analysis/cross-review misses remain documented. No release-blocking shipped file-tool defect was observed within the tested scope; this does not establish semantic completeness or runtime enforcement.

At the maintainer's request, npm `latest` now points to `0.1.0-alpha.8`; `next` remains `1.0.0-rc.1`. The alpha remains a prerelease, with its original Claude-only configuration-target scope. This channel change does not approve stable 1.0.0.
