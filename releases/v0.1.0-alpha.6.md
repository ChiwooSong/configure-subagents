# 0.1.0-alpha.6 — guarded Skill updates

Prerelease date: 2026-10-19 (Asia/Seoul). npm channel: **`next`**. **1.0.0 remains on hold.**

Previously, downloading a newer CLI did not update the Skill already copied into a project: `install` refused differing contents. This release adds an explicit `update` command for recognized, unmodified older installations.

```sh
npx --yes @woody_s/configure-subagents@next update --agent all
```

Use `--agent claude` or `--agent codex` when only one host is installed; `--project` and compatible `--host` selectors work for updates too. For reproducibility, replace `@next` with `@0.1.0-alpha.6`. New installations still use `install`.

## Changes

- Upgrade complete unmodified Skill trees matching published unscoped alpha.1 or scoped alpha.2/4/5 fingerprints. Identification is offline and does not execute old package code or trust local version markers.
- Preserve customized/unknown installations. Edits, additions, deletions, extra directories and line-ending changes cause a conflict before either selected host changes. Differing paths are reported for manual comparison; there is no force overwrite or automatic merge.
- Preserve current installations unchanged, including file modification times and no extra backup creation.
- Stage replacements and keep exact originals under the project's `.configure-subagents-updates/<transaction>/backups/<host>/`, outside Skill discovery. Recheck file identities/content before moving, and conditionally restore originals on handled failures. Concurrent changes are retained with recovery paths reported.
- Keep existing `.claude/agents`, other Skills, project source and global settings untouched. No models are invoked and no Python dependencies are installed.
- Explain the distinction between the downloaded CLI version, copied Skill files and npm's `latest`/`next` tags in the README. This release updates `next` only; `latest` remains the older alpha.2, not a stable release.

## Validation

- **59 Node tests**, including published-version upgrades, custom-content refusal, rollback, concurrent edits, symlink/junction boundaries, Unicode paths and repeat preservation.
- **56 Python tests**, Skill structure/reference validation and skill-creator validation.
- Actual **17-file npm tarball** installation and alpha.5 update for both hosts, with payload, repeat and existing-Agent preservation checks.
- The exact commit's six cross-platform CI jobs and public-registry verification are recorded with this release. See the [detailed update report](../evals/UPDATE_COMMAND.md).

## Limits and recovery

Updates require every selected host to be installed; missing hosts stop the operation. For custom content, install into a separate temporary project and manually compare/merge after backup. Keep reported backups until the updated Skill is checked; the CLI does not clean them automatically or edit your `.gitignore`.

Two-host replacement is not crash-atomic: process termination or power loss can leave staged/backup directories requiring manual recovery. Filesystem checks are not isolation from a hostile concurrent writer. See the [README update and recovery procedure](../README.md#updating-an-existing-skill).

**The Claude behavior limitation disclosed in alpha.5 remains.** In the evaluated Windows / Claude Code 2.1.302 / `claude-opus-5-5` combination, required fresh source cross-review was skipped and a broad worker retained a universal fix-to-green procedure conflicting with reproduction/design-only assignments. A no-edit repeat did not detect that contradiction. This is a bounded observed limitation, not a claim about every Claude model. No new authenticated host sessions were run for this installer change. Static validation and successful updates do not establish semantic completeness, model access, Skill discovery or generated-Agent invocation.

The [1.0.0 checklist](../docs/V1_RELEASE_CHECKLIST.md) remains open; this update does not close host-behavior blockers.
