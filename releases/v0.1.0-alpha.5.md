# 0.1.0-alpha.5 — evidence retrieval and preservation

Prerelease date: 2026-10-18 (Asia/Seoul). npm channel: **`next`**. **1.0.0 remains on hold.**

This alpha improves project-specific evidence gathering and preservation of existing Agent instructions. It does not claim that all host behavior checks pass.

## Changes since alpha.4

- Preserve the existing Agent language, encoding/BOM, line endings and final newline independently of the user's report language.
- Require a concrete configuration defect before editing; adequate configurations should retain bytes and modification times on repeat.
- Inventory evidence across independent assignment, handoff and review areas before drafting execution boundaries. Compare actual candidate restrictions against source conditions before installation.
- Add two read-only Python standard-library helpers: `find_evidence.py` for paginated literal-term source inventories, and `inspect_file_bytes.py` for measured formatting, hashes and modification times. Neither installs dependencies or invokes project code.
- Clarify verified target-model eligibility, operation-specific exceptions, tool interfaces versus behavioral rules, accurate check reporting, and permitted temporary-output locations.
- Retain previous failed and partial evaluations alongside the new results; raw project copies, private paths and session logs are excluded from Git and npm.

## Known Claude limitation

In the tested **Windows / Claude Code 2.1.302 / `claude-opus-5-5`** combination, first-pass analysis and exception cross-review remain unreliable. R8 found and represented the previously missed isolated-Mac verification condition before the first draft. However, Claude installed its configuration without the required fresh candidate/source comparison, and a broad worker retained a universal fix-to-green procedure despite reproduction/design-only assignments. A fresh no-edit repeat did not detect that conflict.

This is an observed limitation of this host/model/scenario, not evidence that every Claude model fails or proof of an intrinsic model cause. Compare generated restrictions with applicable assignments, revisions and handoff/result evidence before relying on them. Proposal mode supports that review. **Static validation and a no-op repeat do not certify semantic completeness.** Disclosure allows an informed alpha preview; it does not close the stable-release gate.

## Install or update

```sh
npx --yes @woody_s/configure-subagents@next install --agent all
```

For a pinned version, use `@0.1.0-alpha.5`. `--agent claude`, `--agent codex`, `--project`, and the compatible `--host` options remain supported. The installer copies the Skill; it does not modify project Agents or run a model.

Existing copied Skills are not automatically upgraded. Install into a separate temporary project, back up customized Skills outside discovery folders, and compare/merge the complete payload, including the two new scripts. Different contents intentionally cause a conflict; there is no force-overwrite option. See the [README update procedure](../README.md#updating-an-existing-skill-to-alpha5).

The old unscoped package remains deprecated in favor of `@woody_s/configure-subagents`; no old package/version is deleted. This release does not promote `latest` or publish 1.0.0. The existing `latest` tag points to an older alpha and is not a stable-release signal.
