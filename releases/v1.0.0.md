# 1.0.0 — Claude Code and Codex Agent configuration

Release decision: November 3, 2026 (Asia/Seoul). Channel: **latest**. The maintainer explicitly accepted the documented unverified scopes and model/host limitations, approved stable publication and chose to skip rc.2. Acceptance does not turn unverified operations or retained failures into passes.

## Scope and promotion

Run the Skill from Claude Code or Codex. It analyzes project evidence and proposes, creates, improves or validates Claude `.claude/agents/*.md` and Codex `.codex/agents/*.toml`. Without an explicit target, it uses the execution host; either host can explicitly target Claude, Codex or both. `--agent all` installs the Skill in both hosts and does not generate Agent files.

Stable 1.0.0 keeps all **14 installed Skill files byte-identical to the registry-evaluated 1.0.0-rc.1**. Package version/channel and public documentation change; no new model-behavior evaluation is claimed. The guarded application helper still stages complete candidates outside discovery, validates the checked digest, refuses stale/conflicting/unsupported changes and unapproved deletions, preserves unchanged bytes/mtimes, and conditionally restores only outputs it can identify. It does not supply semantic review, a sandbox, crash-atomic multi-file writes or protection against another program's direct writes.

## Install or update

```sh
npx --yes @woody_s/configure-subagents@latest install --agent all
npx --yes @woody_s/configure-subagents@latest update --agent all
```

Use `install` for a new project and `update` for existing installations; pin `@1.0.0` for reproducibility. Pristine recognized alpha releases upgrade with backups. An unmodified rc.1 Skill already matches stable, so update succeeds without rewriting files or creating backups. Customized Skills are preserved and require manual merging. Existing Claude/Codex Agent files are untouched by installation/update.

Node.js 22+ is required. The CLI has no external runtime dependencies. Python 3.10+ with PyYAML is required for Claude checks; Codex uses tomllib on Python 3.11+ or conditional tomli on 3.10. Installation does not install Python dependencies, invoke models, change global settings or execute generated Agents. Responses follow the requested language; existing Agent instructions keep their established language unless explicitly changed. This is not a claim that all languages were tested.

## Evidence and accepted limits

The [RC behavior report](https://github.com/ChiwooSong/configure-subagents/blob/main/evals/RC1_BEHAVIOR.md) retains **22 session outcomes: 21 native final receipts and one reconciled final-report observation**. Seven native fresh repeats have identical request/start bindings and unchanged observed workspace bytes/mtimes, including transaction records. Process completion, report shape, static validity, semantic judgment and Agent execution are assessed separately.

- **Incomplete real-project context:** all eight real outcomes used frozen captures omitting module sources, including `.mjs`/`.mts` wrappers. The QA harness is fixed and regression-tested; corrected-cohort model sessions were declined. Module-inclusive project behavior remains unverified. Missing input is not a missing original file or a host's failure to inspect supplied source.
- **Claude validation permission block:** validation-only commands were denied by native host permissions. Manual findings and independent static checks do not establish successful host execution.
- **Unrecovered last process exit:** the last Claude real-both repeat produced a final report and current files match recorded apply output, but its window disappeared without a native exit receipt. Return code, elapsed time and separately persisted repeat-start/end binding remain unverified. No receipt was synthesized and no replacement session was launched.
- **Model/host judgment limitations:** first-pass retrieval and cross-review may miss conditional exceptions or retain overbroad workflow/memory-threshold rules. Some outputs did so despite unchanged fresh repeats. Historical model usage was also described too strongly as eligibility in one outcome; the existing model was retained, with present account access unverified. These are observed scenario-specific limits, not proof of an intrinsic cause or all-model failure.
- **Untested runtime and breadth:** generated-Agent discovery/invocation, actual model access, runtime enforcement, performance/cost savings and all languages/OS/model/provider combinations were not established. Windows authenticated host evidence is distinct from Linux/macOS static CI.

No release-blocking shipped file-tool defect was observed within the tested scope. Original projects were not task-edited; concurrent original changes were observed without rollback. Workspace snapshots are not OS-wide write tracing. Read-only/static success is not a security approval or proof of semantic completeness. Review proposed restrictions against current assignments before using them for project work.

## Final release gates

Run the complete Node/Python/Skill suite, all six Windows/Linux/macOS × Python 3.10/3.13 static CI combinations with Node 22, and exact-tarball installation/update/conflict/no-op/helper checks. Verify the published registry integrity, metadata and `latest` version, then repeat smoke checks from the public package. Exact source, CI, artifact and registry receipts accompany the GitHub release. No live model or generated-Agent calls are part of these final checks.
