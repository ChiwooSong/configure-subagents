## Changes and acceptance criteria

R5's Claude execution searched worker/ownership terms and a later task revision, but missed the base assignment's isolated verification exception. Its final report also treated omission of the Agent interface as a process-level restriction despite Bash access. The new Skill requires an operation evidence map before drafting: component verification, operation-specific counterexample searches, applicable base/revision documents, and linked result/review/handoff passages. Tool explanations now separate listed interfaces, behavioral instructions, and observed runtime enforcement.

This changes the evidence retrieval and reporting procedure, not project permissions. Existing adequate conditional instructions still require no edit. Acceptance requires:

- First application reconciles component-specific verification and material restrictions before installation, rather than depending on a later run to find the same source evidence.
- Tool claims identify shell access and do not equate an omitted delegation interface with a verified inability to start processes.
- A fresh identical-request repeat preserves adequate Agent content, language, line endings, and modification times; a justified defect correction is recorded separately from a no-op.
- Original project files are not edited, and unrelated files in the copies remain unchanged.

The same frozen source selection as R5 is used: 687 Signal Flare and 534 Mosigi files from the 2026-10-16 project snapshot. Only Agent configuration in isolated copies and the Skill's static checker are in scope. No generated Agent calls, product tests/builds, device/service access, dependency installation, global settings changes, commits, pushes, or publication. Task-authored helpers must remain in the evaluation root; automatic host logs are distinguished from task outputs.
